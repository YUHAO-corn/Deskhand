# Context Compaction 端到端测试指南

> 日期：2026-04-08
> 目的：验证 Context Compaction MVP（Slice 1-4）功能完整性

## 测试前准备

### 1. 确认实现完整性

已实现的功能：
- ✅ 70% 阈值触发压缩（140K tokens）
- ✅ workspace memory 工具（TaskCreate/TaskUpdate/TaskList/TaskGet/UpdateUserPreference）
- ✅ PostCompact Hook 注入 tasks/user 信息
- ✅ PreCompact Hook 归档转录到 .transcripts/
- ✅ compact.md 压缩提示词

### 2. 启动应用

```bash
bun run dev
```

### 3. 检查初始状态

确认 `.claude/` 目录会自动创建：
- `.claude/tasks.jsonl` — 任务列表
- `.claude/user.md` — 用户偏好
- `.claude/compact.md` — 压缩提示词

## 测试场景

### 场景 1：任务记忆测试

**目标**：验证压缩后 agent 仍然记得当前任务

**步骤**：

1. 创建一个任务：
   ```
   帮我实现一个简单的计数器组件
   ```

2. 确认 agent 使用了 TaskCreate 工具，检查 `.claude/tasks.jsonl`

3. 继续对话，让 agent 开始实现：
   ```
   开始实现吧
   ```

4. 模拟长对话（发送大量消息，触发压缩）：
   - 可以让 agent 读取多个大文件
   - 或者进行多轮代码修改
   - 目标：让 token 使用量接近 140K

5. 压缩触发后，检查：
   - `.transcripts/` 目录下是否有归档文件
   - 文件名格式：`YYYYMMDD-HHMMSS-auto-{sessionId}.jsonl`

6. 压缩后继续对话：
   ```
   我们刚才在做什么？
   ```

**预期结果**：
- agent 能回忆起"实现计数器组件"这个任务
- agent 能继续完成任务，不会忘记上下文

### 场景 2：用户偏好测试

**目标**：验证压缩后 agent 仍然遵守用户偏好

**步骤**：

1. 表达一个明确的偏好：
   ```
   我是产品经理，不懂代码。请用产品语言解释，不要直接发代码。
   ```

2. 确认 agent 使用了 UpdateUserPreference 工具，检查 `.claude/user.md`

3. 验证 agent 遵守偏好：
   ```
   这个组件是怎么工作的？
   ```
   - 预期：agent 用产品语言解释，不直接贴代码

4. 模拟长对话触发压缩（同场景 1）

5. 压缩后再次测试偏好：
   ```
   再解释一下这个功能
   ```

**预期结果**：
- 压缩后 agent 仍然用产品语言解释
- 不会突然开始发代码片段

### 场景 3：对话连贯性测试

**目标**：验证压缩后 agent 能接上最近的对话（Rolling Window）

**步骤**：

1. 进行一段具体的对话：
   ```
   把按钮颜色改成蓝色
   ```

2. agent 修改后，立即触发压缩（通过读取大文件等方式）

3. 压缩后立即追问：
   ```
   刚才改的是什么颜色？
   ```

**预期结果**：
- agent 能回答"蓝色"
- 说明 API 的 Rolling Window 保留了最近对话

### 场景 4：压缩频率测试

**目标**：验证压缩不会过于频繁

**步骤**：

1. 进行正常对话（不刻意触发压缩）

2. 观察 `.transcripts/` 目录

**预期结果**：
- 正常对话不会频繁触发压缩
- 只有在接近 140K tokens 时才触发

## 验收标准

### 必须通过的检查点

- [ ] 场景 1：压缩后任务记忆正常
- [ ] 场景 2：压缩后用户偏好生效
- [ ] 场景 3：压缩后对话连贯
- [ ] 场景 4：压缩频率合理

### 文件检查

- [ ] `.claude/tasks.jsonl` 正确记录任务
- [ ] `.claude/user.md` 正确记录偏好
- [ ] `.claude/compact.md` 存在且包含压缩提示词
- [ ] `.transcripts/` 目录下有归档文件
- [ ] 归档文件格式正确（JSONL）

### 日志检查

观察控制台输出：
- [ ] 压缩触发时有日志
- [ ] PostCompact Hook 执行成功
- [ ] PreCompact Hook 执行成功

## 已知限制

1. **手动触发压缩困难**：需要真实达到 140K tokens，测试成本高
2. **无自动化测试**：当前只能手动验收
3. **压缩效果主观**：需要人工判断 agent 回答质量

## 后续优化方向

1. 添加压缩触发的调试模式（降低阈值到 10K 方便测试）
2. 添加自动化测试脚本
3. 添加压缩效果的量化指标
