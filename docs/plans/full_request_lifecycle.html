路由规则（常驻提示词）
read_me 工具
设计规范（read_me 返回）
渲染管道（Codex 做的）
1
用户说了句话
比如"帮我解释一下 TCP 三次握手"
2
模型看路由规则，判断要不要画图
路由规则在系统提示词里，每次对话都在。模型按优先级清单检查：没有更合适的工具 → 用户没要文件 → 这个话题适合可视化 → 决定画图。
路由规则
3
模型调用 read_me 工具
决定画图了，但还不知道具体怎么画。先调 read_me 传入需要的模块类型（比如 "diagram"），拉取详细的设计规范。
read_me 工具
4
设计规范注入模型上下文
read_me 返回几千字的规范：颜色用什么、字号多大、SVG viewBox 怎么设、常见错误怎么避免。模型现在知道该怎么写代码了。
设计规范
5
模型先输出文字，再写代码
模型先用 text_delta 输出正文："TCP 三次握手是这样的……"，然后调用 show_widget 开始输出 SVG/HTML 代码。
设计规范指导写法
触发渲染管道
6
渲染管道接手
widget_chunk 事件一段段到达 → useAgentEvents 攒进 message.widget → TurnCard 正文后出现 iframe → LiveWidgetFrame 做标签缓冲、增量渲染。用户看到图在"画"出来。
渲染管道
7
流结束，交互就绪
widget_complete 到达 → 脚本激活 → sendPrompt 桥接就绪 → 用户可以点击图里的按钮继续追问。最终 HTML 存入消息记录，下次打开直接渲染完成态。
渲染管道
一句话记： 路由规则决定画不画 → read_me拉规范 → 设计规范指导写代码 → 渲染管道画到屏幕上
